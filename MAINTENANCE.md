# Обслуживание Архива Лороведьмы

Публичная база игровых текстов Тейвата на русском, английском и китайском языках.
Сайт рассчитан на существующий GitHub Pages: `https://lorewitch.github.io/archive/`.
Теперь Архив также работает как устанавливаемое веб-приложение (PWA).
Размещение остаётся на GitHub Pages: дополнительные серверы, аккаунты и платные сервисы не нужны.

## Установка этой версии

1. Распакуй ZIP и перенеси содержимое папки `archive` в корень существующего репозитория `archive`.
2. Папку `assets` замени целиком: при простом объединении папок старые неиспользуемые изображения останутся на диске. Остальные файлы перенеси с заменой.
3. Сохрани служебную папку `.git` своего рабочего репозитория. В ZIP история Git не включена.
4. Загрузи изменения в существующий репозиторий и дождись завершения его сборки и публикации GitHub Pages.

Для Альтер дополнительных изменений не требуется: адрес сайта, маршруты записей и оба индекса бота сохранены. Название репозитория и `ARCHIVE_BASE_URL` менять не нужно.

## Как пользоваться приложением

- На компьютере открой опубликованный Архив в Chrome или Edge. Нажми «Установить Архив» в разделе «Об архиве» либо воспользуйся установкой приложения в меню браузера. Если браузер не предлагает установку, кнопка «Как установить Архив» откроет подсказку.
- На Android воспользуйся той же кнопкой или установкой приложения в меню браузера.
- На iPhone/iPad открой Архив в Safari, затем «Поделиться» → «На экран Домой».

После установки Архив запускается по собственной иконке в отдельном окне. Обычная версия по прежнему адресу тоже продолжает работать. На ПК сохраняются прежние дизайн, разделы и управление.

При первом посещении с интернетом дождись подсказки «Каталог доступен без сети». Каталог и интерфейс сохраняются автоматически. Чтобы читать конкретную книгу, историю или описание без интернета, сначала открой этот материал с подключением к сети. Книга сохраняется целиком, со всеми доступными языками и томами; изображения сохраняются по мере загрузки. Весь Архив заранее не скачивается.

Сохранение ограничено по объёму записей: при длительном использовании старые копии постепенно вытесняются. Браузер также может очистить данные сайта. Поэтому офлайн-копии предназначены для удобного чтения, а не для постоянного резервного хранения.

При наличии новой версии в разделе «Об архиве» появится «Обновить Архив». Обновление применяется по нажатию и сохраняет адрес открытой страницы. При подключении к сети тексты запрашиваются заново; для несохранённого офлайн-материала есть понятная подсказка и повтор загрузки.

Установка и офлайн-режим работают по HTTPS (GitHub Pages уже его предоставляет). Открытие `index.html` двойным щелчком с диска не устанавливает приложение.

## Исходники и сборка

CSS и JS собираются из `src/css/` и `src/js/`:

```bash
python tools/check_source.py
python tools/build_css.py
python tools/build_js.py
python tools/build_pwa.py
python tools/check_archive.py
node --check assets/js/archive.js
node --check sw.js
python -m unittest discover -s tools -p 'test_source.py'
node --test tools/test_client.cjs tools/test_pwa.cjs
```

Не редактируй `assets/css/archive.css`, `assets/js/archive.js` и `sw.js` напрямую: это готовые файлы для сайта. Исходник обработчика офлайн-режима — `src/pwa/service-worker.js`. После изменения публичных файлов запускай `tools/build_pwa.py` последним шагом сборки перед проверками.

После изменения игровых материалов в `content/` выполни полную сборку:

```bash
python tools/build_archive.py
python tools/build_bot_mentions_index.py
python tools/build_bot_runtime_index.py
python tools/check_source.py
python tools/build_css.py
python tools/build_js.py
python tools/bump_cache_version.py
python tools/build_pwa.py
python tools/check_archive.py
node --test tools/test_client.cjs tools/test_pwa.cjs
```

Те же действия автоматически выполняются в GitHub Actions. Для локальных проверок нужны Python 3.11+ и Node.js 20+; у сайта нет серверных зависимостей.

`data/bot_runtime_index.json` — основной компактный индекс Альтер, `data/bot_mentions_index.json` — совместимый полный индекс. Оба нужны. `tools/check_bot_index.py` отдельно проверяет состав записей, адреса, поисковые связи и актуальность компактного индекса. Основной валидатор также запускает эту проверку.

Вспомогательные инструменты: `check_update_package.py` проверяет отдельно подготовленные пакеты обновлений; `prune_bot_index.py` пригоден для удаления карточек без пересборки поисковых правил. После него также нужно пересобрать компактный индекс и запустить проверку.

Подробности прежнего аудита — в `AUDIT.md`, изменений приложения и его проверки — в `PWA_REPORT.md`.

## Если при обновлении видны HEAD и стрелки

Это оставшиеся в файле маркеры конфликта Git. Замени `index.html` целиком исправленным файлом из сборки, без объединения старой и новой версий. На 13 ноября такие маркеры были обнаружены в опубликованном `index.html`; в этой сборке их нет. Проверка `tools/check_source.py` находит их в исходниках, а service worker отказывается сохранять такую страницу как новую офлайн-версию.

После замены дождись публикации GitHub Pages. Если браузер продолжает показывать старый интерфейс, открой «Об архиве» и нажми «Обновить Архив», когда кнопка появится.
